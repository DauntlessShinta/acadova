# P3.2 CreditTransaction index rollout — approval required

This is a plan, not an executed migration. Do not deploy opening-grant writes until the production `credittransactions` indexes are verified and changed under a separately approved maintenance procedure. The existing unique `{ session: 1 }` index (normally `session_1`) treats missing Session values as the same key, so it would reject the second opening grant.

1. Back up the collection and inspect `db.credittransactions.getIndexes()` and counts of rows missing `type`, `session`, or `toUser`. Stop for manual review if historical payment rows lack the fields needed for the new partial predicate or if unexpected duplicate evidence exists. Confirm the old unique Session index name; do not assume it is `session_1`.
2. While the old unique index still protects payment rows, create and verify these named unique indexes on `credittransactions`: `{ session: 1, type: 1 }` with `partialFilterExpression: { type: 'session_payment', session: { $exists: true } }`, name `uniq_session_payment_session`; and `{ toUser: 1 }` with `partialFilterExpression: { type: 'initial_grant', toUser: { $exists: true } }`, name `uniq_initial_grant_recipient`. The compound payment key deliberately differs from the legacy index key while retaining Session-prefix lookup. The current Mongoose schema declares both, but production index changes must be verified explicitly.
3. During a controlled deployment window, prevent old application instances from recreating the old index. Only after both new indexes are confirmed, drop **only** the inspected legacy unfiltered unique Session index by its exact name. Verify the new indexes remain. Keep verification traffic paused or expect retriable errors until the old index is gone; an aborted verification transaction retains its token and balance.
4. Deploy/enable the P3.2 application only after the index swap, then exercise registration, one verification/grant, a repeated token, and an ordinary Session payment. Check balances and ledger rows. Do not backfill existing accounts or rewrite historical Sessions.

The `CreditTransaction` model has production `autoIndex` disabled, and the application calls no `syncIndexes()` or `dropIndex()`. A failed or partial index rollout requires operator review before verification is re-enabled; do not bypass the unique indexes. MongoDB multi-document transactions are required for verification grants and Session settlement.
